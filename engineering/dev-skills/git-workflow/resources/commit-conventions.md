# Commit conventions

## Types

| Type | Use for |
|---|---|
| `feat` | new user visible capability |
| `fix` | corrected defect |
| `perf` | measured performance improvement |
| `refactor` | structure changed, behaviour identical |
| `test` | tests added or corrected |
| `docs` | documentation only |
| `style` | formatting only, no code meaning changed |
| `build` | build system, bundler, packaging |
| `ci` | pipeline configuration |
| `chore` | dependencies, ignore rules, tooling, maintenance |

## Splitting a feature

A feature is not one commit. A typical vertical slice:

```
feat: add invitations table and migration
feat: add invitation service with expiry rules
feat: add team invitation endpoint
feat: add invitation dialog to the members page
test: cover invitation duplicates and quota limits
docs: document the invitation flow
```

Six commits, six revertible units, six readable messages. One commit named
`feat: team invitations` touching thirty files is a diff nobody reviews.

## The `and` test

If the summary needs `and`, split it.

```
Bad   fix: correct total calculation and add missing index
Good  fix: correct discount rounding in the order total
      perf: add index on orders.customer_id
```

## The revert test

If reverting the commit would break something unrelated, it is two commits.

## Bodies

Written only when the summary is insufficient. The body explains why, and what
was rejected.

```
fix: compute invoice totals from stored prices

The client sent a unitPrice which the server used directly, so a modified
request could order at any price. Prices are now read from the products table
by id.

Rejected: validating the client price against the stored one, which still
requires the lookup and adds a failure mode with no benefit.
```

## Referencing work items

Follow the project's habit, read from `git log`. Do not introduce a new
referencing style.

```
fix: handle expired payment session (#412)
```

## What never appears

```
Co-authored-by: any assistant or tool
Generated by, Created with, Assisted by
any mention of Claude, an AI, an assistant, a bot or a model
a secret, a token, a key, an internal URL with credentials
an apology, a mood, or a note to self
```

## Verifying a session's history

```bash
git log --format='%h %an <%ae> %s' -20
git log --format='%b' -20 | grep -iE 'co-authored|generated|assistant|claude|\bai\b'
```

The second command must return nothing. When it does not, amend or rebase
before pushing.

## Amending safely

```bash
git commit --amend --no-edit          # last commit, not yet pushed
git rebase -i --autosquash <base>     # several commits, personal branch only
```

Never amend or rebase a commit that exists on a shared branch. The cost of a
bad message on a shared branch is lower than the cost of rewriting history
other people have pulled.
