# Task article checklist

Per article, before it is published.

## Title

- [ ] Names a task, not a feature, screen or module.
- [ ] Uses a verb the reader would use.
- [ ] Could have been typed into a search box by someone who does not know the
      product.
- [ ] Distinguishable from every other article at a glance.

## Opening

- [ ] One line stating what this achieves and when you would want it.
- [ ] Prerequisites listed before the first step: access, permissions, data,
      anything to have ready.
- [ ] Anything irreversible is flagged here, not discovered at step 6.
- [ ] Estimated effort where the task is long, in steps or minutes.

## Steps

- [ ] Numbered.
- [ ] One action per step. No step contains the word `then`.
- [ ] Every step states what the reader sees afterwards.
- [ ] Interface labels quoted exactly as they appear.
- [ ] Between five and nine steps, or the task is split.
- [ ] Executable with the images removed.
- [ ] No step assumes a privilege not listed in the prerequisites.

## Result

- [ ] The reader can tell, without help, that it worked.
- [ ] Stated as something observable, not as a claim that it is done.

## Failure content

- [ ] Three to four failures, taken from real support tickets.
- [ ] Error messages quoted exactly, including punctuation and capitalisation.
- [ ] Each has a cause in one sentence, without blaming the reader.
- [ ] Each has an action, and names who to contact when the action is not the
      reader's to take.

## Language

- [ ] Second person, present tense, active voice.
- [ ] Imperative for actions.
- [ ] No `simply`, `just`, `easily`, `obviously`, `of course`, `all you have
      to do`.
- [ ] No system vocabulary that is not glossed on first use.
- [ ] One term per concept, matching the glossary.
- [ ] No jargon inherited from the codebase.

## Images

- [ ] Every image supports a step that is executable without it.
- [ ] Cropped to the control plus enough context to locate it.
- [ ] Captioned with what it shows.
- [ ] No instructional text living only inside an image.
- [ ] No real personal data, and fictional data consistent across the document.
- [ ] Product version and capture date recorded.

## Verification

- [ ] Every procedure was performed in the product, in order, from a fresh
      account with the minimum privileges stated.
- [ ] Someone unfamiliar completed the task using only this article.
- [ ] Every hesitation they had was fixed, not explained away.

## Maintenance

- [ ] Owner recorded.
- [ ] Product version and date recorded.
- [ ] The change that invalidates this article is named.
- [ ] Links to related tasks, not to a category page.

## The two failures this checklist exists to catch

A feature-shaped title makes the article unfindable by the person who needs
it. A paraphrased error message makes it unfindable at the exact moment it is
searched for. Both produce documentation that is correct, complete, and never
read.
