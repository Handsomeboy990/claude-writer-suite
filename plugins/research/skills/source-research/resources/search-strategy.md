# Building a search strategy

A search without a strategy returns the loudest sources, not the best ones. Build
the strategy before searching, and it doubles as the record of how the answer was
found.

## The four parts

### Terms
- The everyday phrasing of the question.
- The terms of art the domain uses: the legal term, the clinical name, the
  standard's number, the API's actual method name. A domain's own vocabulary
  finds its own primary sources; a layperson's phrasing finds aggregators.
- Synonyms and older names, so a source using a different term is not missed.

### Target sources
- Name where the top-of-ladder answer lives before searching: the official
  registry, the journal database, the vendor's docs, the primary corpus, the
  code repository. Go there directly, not only through a general web search.
- A general web search is for orientation and for finding routes to primaries.

### Angles
- Phrase the query from more than one direction, including the opposing view.
  A question searched only in the phrasing of the desired answer returns only
  that answer's supporters.
- Search for the criticism, the counter-evidence, the exception.

### Stop rule
- Saturation: new searches return sources already seen. That is when to stop.
- Not fatigue, not the first confirming source, not a round number of results.
- If saturation is not reached because a source is unavailable, that is a stated
  gap, not a reason to stop early and pretend completeness.

## Recording the strategy

Keep the terms, the target sources, the angles and what each returned. The record
lets someone else repeat the search, and it shows whether the source set skews to
one viewpoint. A strategy that only ever searched in the desired answer's terms is
visible in its own record.
