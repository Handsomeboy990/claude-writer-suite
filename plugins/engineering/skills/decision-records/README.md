# decision-records

Records why a system is built the way it is: context, forces, options actually
considered, the decision, the consequences accepted, and what would reverse
it. One page, written once, never edited.

- Inputs: the decision, the constraints that produced it, the options weighed.
- Outputs: decision record, decision index, superseding records.
- Depends on: engineering-core.
- Lateral: architecture-design, technology-selection, technical-debt.
- Downstream: technical-documentation, project-continuity, client-handover.

Records are immutable: a change of mind produces a new record that supersedes
the old one. Editing an accepted record destroys the only artefact that shows
what was true at the time.
