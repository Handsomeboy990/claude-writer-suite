# Example: building a profile for a backend engineer targeting staff roles

A backend engineer with seven years across three companies wants to target staff
engineer roles. The profile is built as the source everything else will read.

## Skill inventory, honest levels

```
technical
  Go, Postgres, distributed systems      independent, strong evidence
  Kubernetes                              independent, one production migration
  system design                           independent, led two
  Rust                                    learning, one side project
  ML infrastructure                       aware of, no production work

interpersonal
  mentoring                               independent: mentored four juniors
  cross-team leadership                   partly: led within a team, not across
  written technical communication         independent: RFCs adopted org-wide
```

The "cross-team leadership: partly" is the honest entry that shapes everything
else, because staff roles ask for exactly that.

## Experience, quantified

```
Senior Engineer, <company>, 2022-now
  - Led the migration off a monolith to services: cut deploy time from 40 min to
    6, reduced incident rate by a third over two quarters
  - Authored the API standards RFC now used by all six backend teams
  - Mentored four engineers, two promoted to mid-level

Engineer, <company>, 2019-2022
  - Built the billing pipeline handling <scale> transactions/day
  - On-call rotation lead; cut mean time to recovery from 90 to 35 minutes
```

Every number is real. These are the exact results the CV and the interview will
reuse.

## Target requirements, from real staff listings

```
from actual postings, staff backend roles ask for:
  technical depth               met, strongly
  system design at scale        met
  cross-team technical leadership   PARTLY: the profile's central gap
  driving org-wide standards    met (the RFC)
  mentoring                     met
```

## The gap and its path

```
gap        cross-team leadership: the candidate has led within a team and driven
           one org-wide standard, but has not formally led an initiative across
           teams, which staff roles centre on
close it   a named plan: propose and lead a cross-team reliability initiative in
           the current role over the next two quarters, converting "partly" into
           evidence; meanwhile, the CV and interview lead with the RFC, which is
           the closest real evidence of org-wide influence
```

## Narrative

```
The through-line: increasing scope of technical influence, from owning a service,
to owning a pipeline, to setting standards across six teams. The staff move is
the next honest step on that line, and the one gap (formal cross-team leadership)
is named with a plan, not hidden.
```

## What the profile produced

A CV that leads with the RFC and the quantified migrations, a search filtered to
staff roles where the candidate genuinely competes, interview prep centred on the
one gap, and a two-quarter plan to close it. Every downstream skill reads this,
so none of them reinvents the candidate.
